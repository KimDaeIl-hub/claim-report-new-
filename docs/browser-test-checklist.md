# 브라우저 사용자 시나리오 테스트 절차서 (PROMPT 25)

> 자동화 불가 항목을 사용자가 직접 실행하는 절차서.
> 결과는 각 항목에 `[ ]` → `[x]`(통과) / `[!]`(실패·사유 기록)로 표시한다.
> 테스트 전용 명칭은 `[테스트 전용] 직접입력 검증용 제품`을 사용한다 (실제 데이터와 혼동 금지).

## 준비

- [ ] `npm run dev` 실행 후 `http://localhost:3000` 접속
- [ ] 기존 보관함 보고서가 그대로 있는지 확인 (삭제·초기화 금지)

## 시나리오 A. 기존 Master 제품 선택

1. [ ] [+ 신규 클레임] → [클레임 조사] 진입
2. [ ] [제품 Master에서 선택] → `비타500` 선택 (A/B/C 3건이 구분 표시되는지 확인)
3. [ ] 제품명·제조처·라인에 `Master 연결됨` 배지가 표시되는지 확인
4. [ ] 제조번호 입력 → 조사 내용 1줄 입력 → 더보기 [지금 저장]
5. [ ] 보관함에서 저장 보고서 재열기 → 제품명·연결 정보 동일 확인

- [ ] A-4 저장 유지 통과
- [ ] A-5 재조회 동일 통과

## 시나리오 B. 미등록 제품 직접입력

1. [ ] 신규 클레임 → 제품명에 `[테스트 전용] 직접입력 검증용 제품` 입력
2. [ ] `직접 입력` 배지 표시 확인 (Master 연결됨이 아니어야 함)
3. [ ] 제조처·라인도 임의 텍스트로 직접 입력 → 각 `직접 입력` 배지 확인
4. [ ] 조사 내용 입력 → 저장 → 닫고 보관함에서 재열기 → 값 유지 확인
5. [ ] 품질 지식센터 → 제품/제조처 탭에서 테스트 명칭이 **없는지** 확인 (자동등록 방지)

- [ ] B-4 유지 통과
- [ ] B-5 자동등록 없음 통과

## 시나리오 C. Master 선택 후 텍스트 수정

1. [ ] Master 제품 선택 → 제품명을 `비타500 200mL(수정)` 등으로 변경
2. [ ] 배지가 `직접 입력`으로 전환되는지 확인
3. [ ] 저장 → 재열기 → 수정 텍스트 유지 + ID 미연결 상태 유지 확인
4. [ ] 이전 제품의 제조처·라인·공정 텍스트가 그대로인지 확인 (삭제 여부)
5. [ ] [제품 Master에서 선택]으로 원래 제품 재선택 → ID·표시 복원 확인
6. [ ] 제조처·라인도 동일 절차 반복

- [ ] C-3/C-4 통과
- [ ] C-6 복원 통과

## 시나리오 D. 제품·라인·공정 연결

1. [ ] A/B/C라인의 `비타500`을 각각 선택 → 라인·공정이 올바르게 바뀌는지 확인
2. [ ] 조사 패키지 적용 후 선택한 제품·라인·공정 유지 확인
3. [ ] 제품명 직접 수정 후 이전 공정 흐름 텍스트가 그대로인지 확인

- [ ] D 통과

## 시나리오 E. 소비자 문서 표시

1. [ ] 품질 지식센터 → 제품 탭에서 `[실제]` 표기 확인 (관리 화면, 정상)
2. [ ] `[실제]` 제품으로 보고서 작성 → 미리보기에서 제품명 확인
3. [ ] 이메일 회신 본문에서 제품명·제조처 확인
4. [ ] 인쇄 미리보기에서 동일 확인
5. [ ] `[실제]` 접두사가 소비자 문서에 노출되는지 기록 (현재 사양: 노출됨 — 하단 §E 참조)

- [ ] E-1 관리 표시 통과
- [ ] E-5 노출 여부 기록 (통과/실패가 아닌 사실 기록)

## 시나리오 F. 기존 기능

1. [ ] 과거 클레임 검색 → 상세 조회 → 구조 가져오기
2. [ ] 표준 상용구 클릭 삽입 → 원문 일치 확인 (붙여넣은 문장과 라이브러리 문구 대조)
3. [ ] 조사 패키지 적용 → 보고서 저장 → 재조회
4. [ ] 기존 보고서 열기 → 수정 → 저장 (값 유실 없음)

- [ ] F 통과

## 제조공정 ID 점검 (분석 결과 기반)

- 코드상 `factoryId`는 출처 기록용이며 보고서 출력은 흐름 **텍스트** 기준.
- 흐름 텍스트 수정 후에도 기존 ID가 유지되는 것은 정상(수정 제안 없음).
- 연결 preset 확인이 필요하면 품질 지식센터 → 제조공정 탭에서 대조.

## Seed 적용 확인 절차 (PROMPT 1-1, `/?seed=demo` 1회 적용 후)

1. [ ] 품질지식센터 → 등록 현황 펼치기 → 저장 건수 확인
2. [ ] 제품 탭에서 `비타500` 검색 → A/B/C 라인별 3건 구분 표시 확인
3. [ ] 제조처 탭에서 `[실제] 광동제약 식품공장` 확인
4. [ ] 제조공정 탭에서 `[실제]` 공정 3종 + 단계 표시 확인
5. [ ] 신규 클레임 → [제품 Master에서 선택] → `[실제] 비타500` 선택 → 라인·공정 자동 연결 확인
6. [ ] 상용구·과거클레임 탭 정상 동작 확인 (기존 기능)
7. [ ] 새로고침 후 등록 현황 건수 동일 확인 (중복 없음)

## 브라우저 저장소 직접 확인 절차 (PROMPT 1-2, 개발자도구 콘솔, 읽기 전용)

> 아래 명령은 조회만 수행하며 저장소를 변경하지 않는다.
> `?seed=demo` 적용 전후에 각각 실행하여 건수를 대조한다.

```js
// 1. 영역별 저장 건수
["kwangdong_product_master_v1","kwangdong_manufacturer_master_v1","kwangdong_manufacture_line_master_v1","food_qc_custom_factory_process_presets_v1","kwangdong_process_step_master_v1"].forEach(k=>{try{const v=JSON.parse(localStorage.getItem(k)||"[]");console.log(k, Array.isArray(v)?v.length:v)}catch(e){console.log(k,"parse-error")}});
```

```js
// 2. 자사(company-*) 등록 건수
const J=k=>JSON.parse(localStorage.getItem(k)||"[]");
const prods=J("kwangdong_product_master_v1");
console.log("자사 제품:", prods.filter(p=>p.id&&p.id.startsWith("company-prod-")).length, "/ 기대 35");

console.log("자사 공정:", J("food_qc_custom_factory_process_presets_v1").filter(f=>f.id&&f.id.startsWith("company-process-")).length, "/ 기대 3");
```



## 테스트 데이터 정리 절차 (§4)

1. 보관함(서랍)을 연다 → 테스트 보고서 우측 삭제 버튼 클릭
2. 확인 대화상자(`이 보고서를 보관함에서 영구 삭제하시겠습니까?`)에서 확인
3. 삭제 범위: 보관함 키(`food_qc_saved_reports_v1`)에서 해당 ID만 제외.
   초안·Master·지식·상용구에는 손대지 않음 (코드 확인済, `handleDelete`)
4. 삭제 후 보관함 목록에서 해당 보고서가 없는지, 다른 보고서가 그대로인지 확인
5. 정리 필요 보고서 식별 정보는 아래에 기록:

- 보고서 ID:
- 문서번호:
- 정리 완료 여부: [ ] 완료 / [ ] 보류(사유: )
